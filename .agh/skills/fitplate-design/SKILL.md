# FitPlate 设计方法（通用）

本 Skill 只讲*怎么做*，不含任何固定孔位、固定中心或参考答案。所有数字以冻结任务
（`input/tasks/<task_id>/task.json`）与冻结场景为准；任务之间可以互相矛盾地要求不同
的中心范围、板宽或间隙，一律以当前任务为准。

## 0. 只使用本项目工具

需求整理阶段调用 `fitplate_get_request`、`fitplate_propose_constraints`、`fitplate_commit_task`；
冻结后调用 `fitplate_load_task`、`fitplate_build_candidate`、`fitplate_validate_candidate`、
`fitplate_get_run`、`fitplate_export_package`，共八个产品工具。仅为读取当前会话真实附件的
官方引用允许 read `session-file://list` 及该会话附件，不用 shell。不要读取任务目录之外的文件，
不要把输入目录以外（源码、测试、评审记录）的内容当作任务信息。不要输出内部推理过程；
公开说明把「操作目的/待验假设」与「实测结论」分开：目的与假设只陈述想验证什么、为什么选
这个方案，不写成测量结果；实测结论只来自当次绑定报告的实测值。

中文请求全程用中文回复；已有的或必要的公开进度说明、工具前说明也用中文（技术
ID、路径、单位可保留原文），无需为每次工具调用额外增加说明。
草稿说明简述状态、待处理项和锁定/许可，完整数值可在确定性确认卡核对；如复述数值，
保留输入字段、单位及坐标系，不补写输入没有的坐标换算、变化或其他事实。
先读当前请求并登记程序草稿；只有 READY_TO_CONFIRM 才请用户点击
面板“确认条件，开始设计”，页面会生成真实确认附件。不要让用户手写 JSON、hash、引用偏移或
自行上传确认文件。NEEDS_INPUT/冲突时只问真正缺失或矛盾的事实，指向表单修改后点击
“让 AI 检查这些要求”生成新 request revision/草稿；旧草稿和旧确认不能用于新输入。

需求工具的 `input_form` 是同一请求的真实表单值，长度均自带单位。要求值、尺寸 editable
许可和位置许可分别以其中的 requirements、plate.editable、mounting.movement_license 为准。
草稿单条 `keep` 仅保留其引用值，不能据此断言该维度没有 editable 许可；表单中的长度
`value=null` 是待补用户事实，不能与草稿中许可域尚未选点的 `value_mm=null` 混淆。

锁定值约束的是模型在当前确认版本中的设计。用户可以直接更正表单事实，点击
“让 AI 检查这些要求”生成新 request revision；更正后的事实仍可锁定，无需为此开放 editable。
editable 授权模型在本版本的许可区间内选择尺寸，与用户更正事实后重新确认是两件事。
不要把旧版本的 locked 解释成禁止用户输入新的事实；也不能在未更正、未重新确认时
替用户改冻结值。

文本提议被校验器拒绝时，不继续编造含义或反复猜偏移。使用当前真实 request_ref 与
request_sha256、**不带 text_proposals** 调用 propose_constraints，登记程序基础草稿，
再按其缺失/冲突项请用户在表单与原文中澄清。基础草稿非 READY 时不能确认或冻结。

`value_mm=null` 配合完整许可区间表示该候选值尚未选择，不是用户遗漏事实。
模型可在明确许可域内选择具体候选位置/尺寸，交由建模和验证工具检查；锁定值保持不变。

## 1. 先读冻结任务，列出固定与可改

调用 `fitplate_load_task(task_id, revision)`。返回中：

- `plate.locked` 与 `plate.editable`：可改尺寸只有列在 `editable` 里的维度，且**必须显式取值**
  （不能省略、不能用默认值）；`locked` 维度必须保持冻结值。
- `base_holes`：底座孔位置/直径全部冻结，任何设计不得移动、增删或改变直径。
- `sensor.allowed_center_x/y`：设备中心允许范围；`allowed_rotation_deg` 当前恒为 `[0]`。
- 公开正文的 `frozen sensor geometry` 与 `frozen scene geometry` 是冻结输入，不是测量结果。
  选点前读取设备体尺寸、固定件坐标及局部/绝对坐标约定，不按区间上界或下界猜移动方向。
- `requirements`：孔边材料、孔间材料、自由间隙的下限。
- `budget`：任务剩余预算与候选数量上限。

缺关键输入时工具返回 `NEEDS_INPUT`：把缺的字段原样报告给用户并停止，**不要猜测**孔距、
单位或用户锁定位置。完整许可区间内的候选坐标由模型选择，无需追问用户。
返回 `STALE_INPUT` 时重新载入当前 revision，旧结论视为过期。

## 2. 提交 DesignSpec 并建模

用 `fitplate_build_candidate(run_id, design_spec, parent_candidate_id?)`，最小形状：

```json
{
  "run_id": "<load_task 返回的 run_id>",
  "design_spec": {
    "sensor_pose": { "center": [x, y], "rotation_deg": 0 },
    "plate": { "width": <可选：仅当任务允许该维度可改> },
    "note": "本次设计针对的失败项与改动理由（一句话）"
  }
}
```

- `design_spec.task_id`/`task_revision`/`schema_version` 与外层 `task_revision` 可省略，由冻结
  run 补齐；显式给出时仍会被核对，错值拒绝（`schema_version` 错误由工具参数 schema 直接拒绝）。
- `sensor_pose` **必须显式给出具体中心**：在冻结任务许可区间内选择候选值；这属于设计选择，
  不是猜测用户事实。只能在许可域内改动，不能要求用户替模型完成选点。
- `plate` 可选：给出的维度须为任务许可，省略的维度沿用冻结 task 值；显式改动锁定值会被拒绝。
- `note` 说明改动针对哪个测量结果，不要粘贴推理。
- 每个候选版本不可覆盖；修改即新建版本，用 `parent_candidate_id` 指向上一个版本。
- 返回包含 `step_sha256` 与预览统计。生成器的自检**不是**验收证据。

## 3. 用实际几何验证

`fitplate_validate_candidate(run_id, candidate_id)`：验证器会重新导入实际 STEP，独立测量
G01–G08。把返回的逐项 `status` 与 `reason_code` 当作唯一事实来源：

- `PASS` 才通过；`FAIL` 看 `failed_checks` 的 `reason_code` 和实测失败对象对定位冲突；
  `UNKNOWN`/`BORDERLINE` 不能当作通过，也不会允许导出；
- 修改后必须**全量复核**（所有项），不能只看上一轮失败的项；
- 版本与旧报告错配时工具会返回 `STALE_INPUT`，先重新载入/重验，不要沿用旧通过结论。

## 3.5 坐标映射、对象定位与拒绝处理（通用约束）

- **坐标**：`connector_access.local_xy_range` 等 `local_*` 范围是**设备局部坐标**，必须随当前
  `sensor_pose.center`（及旋转）映射到板坐标后再与固定件比较；`absolute_z_range` 已是绝对
  高度，不再平移。不要把 local 数值直接当绝对坐标使用。
- **对象定位**：G06 的 `objects` 是检查覆盖范围，不是任何对象对；不能单靠该列表确定碰撞或最紧对象对。
  失败定位引用 `measured.worst_pair`/失败 pairs；最小自由间隙严格引用
  `measured.minimum_free_clearance_pair.moving/fixed`（工具文本标为"实测最小自由间隙对象对"），必须与同一报告的
  `minimum_free_clearance_mm`、`required.minimum_free_clearance_mm` 一起说明。
  缺对象对就说未提供，不从通用对象列表补齐，不凭脑内几何猜「大概是谁」。
  G 名称以报告文本为准：G01 实体有效性、
  G02 板体尺寸与姿态、G03 底座通孔、G04 传感器孔组/位姿、G05 孔边与孔间材料、
  G06 装配自由空间、G07 固定条件保持、G08 导出一致性。
- **数值证据**：只引用当次 validate 报告文本/structured 中的实测与 required 值；报告写
  null 或「未提供」时不得编造数字。旧字段 `minimum_clearance_mm` 含允许支撑接触，
  不是自由间隙摘要，不能当自由间隙引用。
- **候选与实测分开**：许可域内的选点是**待验证的设计尝试**，不等于几何可行，更不是最优。
  没有同一对象对在新旧两版报告中的已验证实测对比，不把选点方向说成「尽量远离/靠近」
  某**对象**或已带来「改善/最大化」等结论——那是动机，不是测量结果。报告同一对象对就
  引用新旧实测值；对象对变了就如实说明逐版实测对象对与数值，不编造比较收益。
  新候选尚未验证时，公开说明只陈述具体改动字段及「待验证」，不把「增大间距/远离对象」
  当作已实现的改动效果；实际效果须等该候选绑定报告后再说。
- **矩形板的边界因果**：使用当前报告各边的实测孔边材料判断限制边。板原点固定且孔心/孔径
  不变时，单独增大 width 只移动右边，增大 height 只移动上边，不能增加左/下孔边材料；
  孔间材料也不随板外尺寸增加。不得把不影响当前限制边/对象的字段列为补救方案。
  缺少边界依据时只说明需核对限制项，不猜测有效修法；任何用户事实变更仍需重新确认。
- **改进建议只关联实测限制**：FAIL/BORDERLINE 的解释只说明**当前报告**指出的受限项、
  限制对象与影响字段。提出改动建议时，该字段必须能实际影响报告点名的限制对象
  （例如与被测对象对相关的位姿/尺寸）；未经验证的放宽不保证有效。若无法说明改动与
  实测限制对象的关联，就只请用户重新确认相关条件，不把无关的可调字段举为解法；
  用户事实与锁定值只能经新 revision 由用户确认，模型不擅改。
- **NEEDS_INPUT**：立即停止，按工具文本列出的字段（path/code）明确向用户询问对应输入；
  不要猜测 revision、孔距或单位，也不要先提交候选碰运气。合法许可区间内未选候选值
  不算缺失用户事实，不要求用户另给 Y 坐标。
- **INFEASIBLE**：只解释程序给出的证明字段；它只对当前条件组合成立。未经重新验证，不得
  保证某种放宽（改板宽、移固定件等）一定能解；任何条件放宽都需用户重新确认并走新
  revision，旧结论只对旧条件有效。
- **ERROR/UNKNOWN**：如实报告执行故障或未知状态，绝不改写成「无解」或「通过」。

## 4. 修订循环（最多三轮）

1. 每次只针对报告中**实测**失败项修改 `design_spec` 中任务允许的字段；
2. 再次 build + validate；
3. 同一参数组合重复出现、预算耗尽（`BUDGET_EXHAUSTED`）或连续无进展时停止；
   预算内没找到不等于数学无解——只有可核对的矛盾（例如冻结尺寸与要求数值直接冲突）
   才能向用户说明「该固定域不可行」，并附上测量依据；
4. 工具报 `ERROR`（生成/读取/内核故障）时如实报告执行故障，不要改写成设计无解。

## 5. 导出与报告

- 通过后调用 `fitplate_export_package(run_id, candidate_id, report_id)`；导出会重新核对
  每个产物的哈希与报告绑定，报告不 PASS 时会被拒绝（除非显式允许导出失败件，且必须
  标注为未通过）。
- **简短完整收尾**：用中文四项说明交付状态、主要改动、关键实测（含最紧对象对与要求值）、
  当前版本下载入口和软件验证范围。通常 200–350 字即可；写完整句子，不再逐项抄写全部检查、
  哈希、预算、内部文本提议或引用偏移。明细保留在工作台和下载报告；没导出就明确尚无交付包。
- **来源与范围必须照工具文本写，不得合并成一句「参数全部取官方值」**：区分哪些来自
  厂商数据（`input_provenance.source` 里 `device_interface … vendor datasheet` 一项）、哪些
  是用户输入或自设假设（plate/base holes/requirements/environment 各项，`design_assumption`
  就是假设而非实测数据）；来源缺失时写 unknown，不得默认成厂家。
- **只通过软件几何验证**：本工具在冻结输入上做 CAD/几何检查，`verification_scope` 是
  `software_geometry_only`——未做实物装配、材料强度、打印公差实测或传感器性能验证；来源
  声明不构成厂家/官方已验证。
  输入来源里的 `review_status` 是登记时的静态元数据，不是当前候选验证状态；如需引用，
  明确标为输入来源登记状态，当前几何是否通过仍以本候选的绑定报告为准。
- 引用自由间隙时给出当前绑定报告的实测对象对、数值和要求值；允许支撑接触
  （`support_contact`）不是碰撞/干涉，不得混说。
- 若最终未通过：如实给出当前状态、失败项与依据，不夸大结论、不声称已交付合格版本。
