# FitPlate AGH plugin (T06/T08, part of T10) — actual API

The native AGH side of FitPlate: eight tools (five CAD and three intake), one versioned run
store on disk, and four read-only query services the workbench panel reads.
This file records what the code *actually* does, so the frontend batch can wire
against it without guessing.

Plan3 delivery facts are shared by native summaries and the browser through
`src/report-facts.mjs`. G06 text gives the reported `minimum_free_clearance_pair`,
measured value and requirement together. `objects` is labelled as check scope;
support contact and the failed/worst pair remain separate. Missing/null values
never become an invented zero clearance or a guessed pair.

`fitplate.run.versions[]` now includes registered `files` (name/bytes/SHA only),
`report_file_sha256` (raw report bytes) and `report_sha256` (the bridge's canonical
content digest). `fitplate.scene.binding` carries the same distinct identities.
`fitplate.run.exports[]` carries STEP, raw-report and report-content digests as
well as candidate/report identity. These fields permit freshness checks and
prevent an old export with a reused report ID from becoming current delivery.
Legacy incomplete metadata stays explicitly unverified. No query accepts a path
or adds a write capability. Intake confirmation attachments continue to be
generated by the existing page; users are not asked to author JSON or hashes.

```
plugin/
├── package.json                     # agnes.plugins -> runtime; clientDescriptors -> agnes.client.json
├── src/
│   ├── runtime.mjs                  # Cordis plugin entry: Config + apply(ctx, config)
│   ├── tools.mjs                    # the five tools (TypeBox params, 8-key ToolMeta)
│   ├── services.mjs                 # fitplate.run / fitplate.scene / fitplate.artifact
│   ├── run-store.mjs                # exec mediation, envelope checks, bounded verified reads
│   ├── typebox.mjs                  # kind-tagged TypeBox builders (no dependency)
│   └── python_bridge.py             # the only program started through toolCtx.exec
├── client/                          # panel sources (frontend batch)
└── extensions/main/
    ├── agnes.client.json            # client descriptor (same row id)
    └── client/                      # built browser bundle (frontend batch)
```

Row id: `ext:fitplate/plugin` (in-process). The backend row and the client
descriptor declare the same row id, one `workbench.panel` slot and the three
service names; `scripts/test-plugin.mjs --with-agh` cross-checks the descriptor
against `client/build-manifest.json`.

## 1. Execution model

Every side effect goes through `toolCtx.exec`:

```
tool execute(args, toolCtx)
  -> toolCtx.exec([config.pythonPath, config.bridgePath, <subcommand>],
                  { cwd: toolCtx.cwd, stdin: <one JSON request>, timeoutMs })
  -> python_bridge.py  (validates config + session + request; owns the run store)
  -> python -m fitplate.cli build|validate|export --request-stdin   (fresh process, re-reads the STEP)
```

`config.bridgePath` is not a free path: `runtime.mjs` derives it from
`import.meta.url` (the `python_bridge.py` next to the module), so an installed
package snapshot executes its own trusted copy and a config cannot redirect the
row to arbitrary mutable code. A legacy `bridgePath` in the config is accepted
only when it resolves to that same file, and the Python bridge re-checks that
`config.bridge_path` is the running file.

* The plugin itself never spawns a process and never uses `node:fs` on the
  workspace; reads go through `toolCtx.fs` (bounded, hash-verified).
* stdio contract: the bridge writes **one JSON envelope** on stdout and
  diagnostics on stderr. The JS layer refuses a non-zero exit, truncation, a
  mixed/partial stdout, a malformed envelope, or an envelope that names another
  run/candidate/task revision (`EXEC_OUTPUT_MALFORMED`, `IDENTITY_MISMATCH`, …).
* Exit codes: `0` answered (a FAIL report is an answer), `3` business refusal,
  `2` execution failure. Business refusals are normal tool results
  (`ok:false` + `status` + `code`); execution faults additionally set
  `isError:true`.
* No tool accepts a path, a script, a scene object, a hole coordinate or an
  identity. `run_id` is generated by the plugin, `candidate_id` by the run
  store, `task_id` must name a directory under `<workspace>/input/tasks/`.
* Session identity comes from `toolCtx.session` (`key`, `lane`,
  `toolUseId`) — never from tool arguments. Every stored event carries it.

### Config (absolute paths, validated twice)

`plugin/package.json` → `agnes.plugins[0].config`:

```json
{
  "geometryRoot": "/home/Heliora/work/fitplate/geometry",
  "pythonPath":    "/home/Heliora/work/fitplate/.venv/bin/python",
  "runsDir": "runs",
  "tasksDir": "input/tasks",
  "budget": { "commandTimeoutMs": 30000, "taskTimeoutMs": 180000, "maxCandidates": 4 }
}
```

(No `bridgePath`: the executed bridge is derived from the runtime module's own
location. `geometryRoot` and `pythonPath` are this project's explicit external
dependencies; the packaged plugin tree is self-contained otherwise.)

`runtime.mjs` validates it (Standard Schema: absolute paths, in-workspace
relative dirs, integer budgets, unknown keys refused) and the bridge re-validates
it on every call (geometry root must contain `fitplate/cli.py`, the bridge path
must be the running file, the workspace root is the process working directory
set by the Host — never a value from stdin). The model cannot influence any of
it.

## 2. Tools

All five write every ToolMeta key. Writing tools (everything except
`fitplate_get_run`) declare `isReadOnly:false`, `isDestructive:false`,
`isConcurrencySafe:false`, `isOpenWorld:false`, `replay:'never'`,
`requiresApproval:'always'`, and an honest `costHint.wallMs`: publishing a new
immutable version is not a destructive operation, so the
`isDestructive` flag stays false while every write still goes through the
Host's approval gate (the authorized local driver answers it with its own
official `session.onPermissionRequest` handler, and the gate is where F04's
before-validate injection is observed).
`fitplate_get_run` is `isReadOnly:true`, `replay:'safe'`, `requiresApproval:'never'`.

| Tool | Arguments (closed) | Returns |
| --- | --- | --- |
| `fitplate_load_task` | `task_id`, `revision` | run_id, frozen hashes, plate/base holes/sensor envelope/ranges, requirements, tolerances, budget, `status: READY` |
| `fitplate_build_candidate` | `run_id`, `task_revision`, `design_spec`, `parent_candidate_id?` | candidate_id, step/stl hashes, preview counts, duration, budget |
| `fitplate_validate_candidate` | `run_id`, `candidate_id` | report_id, `overall`, full report, failed checks, evidence summary, validator_code_sha256 |
| `fitplate_get_run` | `run_id`, `candidate_id?` | run status, version list with report summaries, exports, budget; no geometry process |

**模型可观察反馈（text 与 structured 分开）**：`fitplate_validate_candidate` 的 content.text 按
G01–G08 规范名称逐项给出 status/reason/objects，并列出**当次绑定报告**实际携带的关键
measured/required 值（G06 的 `worst_pair`/`worst_pair_distance_mm`/`worst_pair_volume_mm3`、G05
的孔边/孔间值等）；报告未提供的字段写 `null（报告未提供）`，不编造；旧字段
`minimum_clearance_mm` 明确标注含允许支撑接触、不是自由间隙摘要（P02-06 的自由间隙摘要实现前
如实说明）。`fitplate_get_run` 的 selected 候选只展示 run manifest 自带的摘要投影（id/status/
objects）并明确标注「逐项实测值不在 manifest 中」。业务拒绝（NEEDS_INPUT/INFEASIBLE 等白名单
状态）的 content.text 携带真实的 `detail.issues`/`missing_paths`/`findings` 可核对字段与数值
边界（字段与长度均有上限）；未知状态或 ERROR 不渲染 detail、也不改写状态。structured 负载与
评分兼容性保持不变。
| `fitplate_export_package` | `run_id`, `candidate_id`, `report_id`, `allow_failed?` | export_dir, file list with hashes, `failed` label, budget |

`design_spec` is the closed DesignSpec surface: `schema_version`, `task_id`,
`task_revision`, `plate{width,height,thickness}?`, `sensor_pose{center,rotation_deg}`,
`note?` — nothing else is accepted (holes, scene objects, paths and scripts are
unknown fields and are refused by the argument schema before execution).

### Status vocabulary the model sees

`READY`, `BUILT`, `VALIDATED`, `EXPORTED` on success; business refusals:
`NEEDS_INPUT`, `INVALID_SPEC`, `LOCKED_CONSTRAINT_CHANGED`, `STALE_INPUT`,
`DUPLICATE_CANDIDATE`, `UNKNOWN_PARENT`, `REPORT_NOT_PASSED`, `STALE_REPORT`,
`EXPORT_EXISTS`, `BUDGET_EXHAUSTED`, `SESSION_MISMATCH`, `RUN_NOT_FOUND`,
`ARTEFACT_HASH_MISMATCH`, `STALE_VALIDATOR`. Execution errors (`isError:true`):
`EXEC_TIMEOUT`, `EXEC_OUTPUT_TRUNCATED`, `EXEC_OUTPUT_MALFORMED`,
`EXEC_OUTPUT_MISSING`, `IDENTITY_MISMATCH`, `BRIDGE_PROTOCOL`, `CANCELLED`,
`BUILD_FAILED`, `STEP_IMPORT_FAILED`, … (the geometry CLI's codes pass through).
A measured `FAIL` report is **not** an error: it is the tool working.

`BUDGET_EXHAUSTED` means "stop; the budget is spent", never "no solution
exists". Timeouts and cancellation are distinct from `CONSTRAINT_FAIL` and
never publish a version.

## 3. Run store on disk

```
<workspace>/                     # toolCtx.cwd, one per model session
├── input/tasks/<task_id>/       # task.json, <task_id>.scene.json, initial-design.json (prepare script)
└── runs/<run_id>/
    ├── manifest.json            # the single source of truth (re-read on every call)
    ├── events.jsonl             # business events bound to session_key/lane/tool_use_id
    ├── run.lock                 # fcntl.flock, serialises every read-modify-write
    ├── input/{task,scene}.json  # byte-frozen copies of the registered inputs
    ├── candidates/v001/…        # model.step, model.stl, preview.json, preview_mesh.json,
    │                            # design.json, task.json, scene.json, build.json, repro.py,
    │                            # report.json, evidence.json   (immutable once published)
    └── exports/<candidate_id>/<report_id>/   # the bundle + export-manifest.json
```

* `run_id` is `r-<base36 time>-<12 hex>`; versions are `v001`…, at most
  `maxCandidates` (default 4 = one initial + three revisions).
* The manifest binds `owner{session_key, lane, workspace_root}`, the frozen
  `task_sha256/scene_sha256/frozen_sha256` **plus** the raw hashes of the two
  frozen input files, the budget, every candidate (hashes, registered file list,
  report summary, validator version **and** `validator_code_sha256`), and every
  export record.
* Publication is atomic: everything is written to `.tmp-*` siblings and renamed
  into place; an existing version directory is never overwritten; a killed or
  cancelled command leaves only its own temporary, which the next run of the
  same command does not touch (no cross-process cleanup).
* Path safety: components are validated as identifiers, every path is walked
  component-by-component for symlinks before use (a symlink inside the
  workspace is refused even when it points at a real directory of the same
  workspace), and the resolved path must stay inside the workspace.
* Geometry commands run with `commandTimeoutMs` (30 s default) and charge the
  run budget (180 s default). Exceeding either stops the run with
  `BUDGET_EXHAUSTED`/`EXEC_TIMEOUT`; nothing half-published remains.
* `validator_code_sha256` is the SHA-256 of the canonical JSON
  `{relative path → file hash}` over `fitplate/{constraints,inspect_step,scene}.py`.
  007 is expected to add the same value as `report.hashes.validator_code_sha256`;
  the bridge's value already matches that algorithm so the two can be compared.

## 4. Query services (actual wire shapes)

Registered through `ctx.services.register`, all `kind: 'query'`,
`timeoutMs: 5000`. `ServiceContext` has no session, `exec` and `write` are
refused by the Host; the handlers only read files of the *current workspace*,
bounded by `stat` before the read and verified against the hashes the manifest
recorded (frozen inputs, candidate artefacts, report, evidence). A
`session_key` from the browser is a **display filter only** — it prevents a
stale panel from showing another session's run; it is not an authorization
credential, and this batch intentionally supports **one workspace per model
session**: nothing can be read across workspaces.

### `fitplate.run`

```jsonc
// input
{ "session_key": "<browser session id>", "run_id": "r-…" }   // run_id optional
// output (found)
{ "found": true, "reason": null,
  "run_id": "r-…", "task_id": "sensor-swap-01", "task_revision": 1,
  "state": "PASSED",                      // manifest status
  "created_at": "…", "updated_at": "…",
  "frozen": { "task_sha256": "…", "scene_sha256": "…", "frozen_sha256": "…", … },
  "budget": { "limit_ms": 180000, "spent_ms": 1234, "commands": 3, "max_candidates": 4, … },
  "task_summary": { "plate": {…}, "base_holes": {…}, "sensor": {…},
                    "requirements": {…}, "tolerances": {…}, "request_text": "…" },
  "versions": [ { "candidate_id": "v001", "parent_candidate_id": null, "status": "VALIDATED",
                  "created_at": "…", "step_sha256": "…", "report_id": "…",
                  "overall": "FAIL", "report_created_at": "…", "validator_version": "…" } ],
  "exports": [ { "candidate_id": "v001", "report_id": "…", "export_dir": "exports/v001/…",
                 "failed": true, "exported_at": "…" } ] }
// no run_id: the newest run of this session_key in this workspace
// miss (stale session key, unknown run, no runs yet)
{ "found": false, "reason": "RUN_NOT_AVAILABLE_FOR_SESSION" | "NO_RUN_FOR_SESSION" }
```

### `fitplate.scene`

```jsonc
// input
{ "session_key": "…", "run_id": "r-…", "candidate_id": "v001" }
// output (found)
{ "found": true, "reason": null, "run_id": "r-…", "candidate_id": "v001",
  "task_id": "…", "task_revision": 1,
  "binding": { "candidate_id": "v001", "step_sha256": "…", "preview_sha256": "…",
               "preview_mesh_sha256": "…", "report_id": "…", "report_overall": "FAIL",
               "design_file_sha256": "…",   // RAW hash of the registered design bytes
               "design_sha256": "…",        // bridge content hash of the submitted design
               "verified": true },          // every read matched its recorded hash
  "device": { "center_xy": [40, 30], "rotation_deg": 0,
              "source": "g04-measured" | "design-fallback",
              "verified": true,             // false + warning when the pose is the unmeasured
              "pose_status": "PASS",        //  design value: render it as an unverified ghost,
              "worst_deviation_mm": 0.0 },  //  never in the accepted/OK style
  "scene": { … frozen SceneSpec … },
  "task":  { … taskSummary as above … },
  "report": { … full ValidationReport (hash-verified file) … } | null,
  "evidence": { "holes": [...], "pairs": [...], "sensor_group": {...}, … } | null,
  "mesh": { "encoding": "json-arrays", "candidate_id": "v001", "step_sha256": "…",
            "triangle_count": 1388, "tolerance_mm": …, "angular_tolerance_rad": …,
            "bounds": { "min": […], "max": […] }, "vertices": […], "indices": […],
            "bytes": 89917, "sha256": "…" },
  "mesh_blocked": null | { "reason": "SCENE_RESPONSE_BUDGET" | "MESH_NOT_RECORDED" |
                                     "MESH_BINDING_MISMATCH" | "ARTEFACT_HASH_MISMATCH" | …,
                           "message": "…", "artifact_id": "preview_mesh.json",
                           "artifact_sha256": "…", "total_bytes": 89917 },
  "design": { … the candidate's registered design.json document … } | null,
  "design_blocked": null | { "reason": "ARTEFACT_HASH_MISMATCH" | "DESIGN_TASK_MISMATCH" |
                                       "DESIGN_UNREADABLE" | "DESIGN_INVALID" | "FILE_TOO_LARGE" | …,
                             "message": "…" } }
// miss
{ "found": false, "reason": "RUN_NOT_AVAILABLE_FOR_SESSION" | "CANDIDATE_NOT_FOUND" }
```

The mesh is the candidate's own `preview_mesh.json` (tessellated from the
published STEP), never re-drawn from design parameters. The whole response stays
≤ 512 KiB: when the mesh would exceed the budget it is dropped and
`mesh_blocked` tells the panel to page it through `fitplate.artifact`. A
frozen-input or artefact hash mismatch is an integrity failure, not a blank
panel: the handler throws and the Host reports the call as unavailable.

`design` is the candidate's **submitted** design document, served through the
same registered-file path (whitelisted name, stat-before-read, 64 KiB cap,
strict UTF-8/JSON, raw bytes hash verified against the manifest): it is display
data for the version diff (`designSummaryFromDocument`), never a measured
result. Two identities are carried and never conflated - `design_file_sha256`
(raw bytes, the one verified here) and `design_sha256` (the bridge's content
hash recorded with the candidate, carried verbatim). The document must name
this run's task and revision; a design registered with another revision/task,
tampered bytes, an unreadable/oversized/malformed file is withheld with an
explicit `design_blocked.reason` instead of being shown beside the wrong run. A
historical candidate with no registered design answers `design: null`
(`design_blocked: null`).

### `fitplate.artifact`

```jsonc
// input (limit ≤ 65536, default 65536)
{ "session_key": "…", "run_id": "r-…", "candidate_id": "v001",
  "artifact_id": "model.step", "offset": 0, "limit": 65536 }
// output (found)
{ "found": true, "reason": null, "run_id": "r-…", "candidate_id": "v001",
  "artifact_id": "model.step", "encoding": "base64",
  "offset": 0, "limit": 65536, "bytes": 65536, "total_bytes": 44416?, "eof": false,
  "sha256": "<whole-file sha256 recorded in the manifest>",
  "chunk_sha256": "<sha256 of the returned chunk>",
  "chunk_base64": "…" }
// miss
{ "found": false, "reason": "UNKNOWN_ARTIFACT" | "CHUNK_LIMIT_EXCEEDED" |
                            "OFFSET_OUT_OF_RANGE" | "RUN_NOT_AVAILABLE_FOR_SESSION" |
                            "CANDIDATE_NOT_FOUND" | "ARTEFACT_HASH_MISMATCH" | "FILE_TOO_LARGE",
  "message": "…" }
```

`artifact_id` must be a file the run manifest registered **for that candidate**
(`model.step`, `model.stl`, `preview.json`, `preview_mesh.json`, `design.json`,
`task.json`, `scene.json`, `build.json`, `repro.py`, `report.json`,
`evidence.json`). There is no path parameter and no arbitrary read: the store
rebuilds the path from the id, checks the size before reading, and verifies the
whole-file SHA-256 before returning any bytes.

## 5. Panel wiring notes (for the frontend batch)

* Poll `fitplate.run` (no `run_id`) to find the current session's newest run,
  then `fitplate.run { run_id }` for state and versions.
* Switch sessions = clear mesh/report/export state, abort in-flight calls and
  drop late responses; a response for a previous `session_key` arrives as
  `found:false` and must not be drawn.
* `device.source === 'design-fallback'` (or `verified:false`) is explicitly not
  a measured result — do not style it as accepted; `report.overall` remains the
  only acceptance signal, and `UNKNOWN`/`BORDERLINE` are never PASS.
* Mesh identity: draw `mesh.step_sha256` / `binding.step_sha256` with the view so
  a version switch can never show the previous geometry under the new report.

## 6. Deployment checklist for this instance

1. **Profile capability**: the isolated instance's `local-dev` profile keeps the
   default capability set and adds `services` (see
   `agnes-harness/docs/develop/fullstack.zh-CN.md`). Without it the three query
   services are refused with `CAPABILITY_DENIED` by policy — that is the correct
   behaviour, not a bug. This file is the project's own instance config
   (`.agh-home/profiles/local-dev/profile.yaml`), never the daily instance.
2. **Prepare a workspace**: `node scripts/prepare-workspace.mjs --task
   sensor-swap-01 --id demo-01` copies only task inputs (no Plan text, no tests,
   no expected results) into `demo-workspaces/demo-01/`.
3. **Install**: `agh package inspect file:./plugin` → `agh package add` /
   `trust` / `enable` with the printed integrity and capabilityHash (the
   snapshot is immutable: editing `plugin/src` afterwards does **not** update
   the installed copy until it is installed again).
4. **Model session**: run a session with `--cwd demo-workspaces/demo-01` so
   `toolCtx.cwd` (and therefore `runs/`) is that workspace.

## 7. Tests

```bash
node scripts/test-plugin.mjs             # all suites (real CAD involved)
node scripts/test-plugin.mjs --fast      # registration + fault injection + path safety
node scripts/test-plugin.mjs --with-agh  # + descriptor/build cross-check and package inspect
FITPLATE_E2E_HOME=<dir> node scripts/test-plugin.mjs --e2e-model   # real model, separate AGH home
```

Suites use Node's built-in `node:test` only. The AGH-contract suite imports the
AGH checkout's own validators through the AGH `tsx` loader and is reported
separately; geometry-backed suites skip themselves with a printed reason when
the project venv or the geometry CLI is missing (a skip is never counted as a
pass — the summary prints the counts).

### Real-model end-to-end (`--e2e-model`)

Runs the whole loop against a real model in a **dedicated AGH home**
(`FITPLATE_E2E_HOME`, never the shared instance — the script refuses
`<project>/.agh-home`): reset the home, write the `local-dev` profile with
`services`, start its daemon, reuse the reviewed DeepSeek credential through
`config.save`, install/trust/enable the plugin through the official package
service, prepare a demo workspace, ask the model to run
`fitplate_load_task → fitplate_build_candidate → fitplate_validate_candidate`,
then verify the native `tool/call` + `tool/result` records in the exported
trajectory *and* the run store the tools wrote. Verified on 2026-10-07 with
`deepseek-flash` (session `agnes:local:local-dev:cli:workspace:d88dcbcea1fa4587`,
run `r-muxh4ek4-e3894af9134a`, v001 measured `G06 SOLID_INTERFERENCE` → `FAIL`).

Three behaviours this E2E pinned down the hard way (all now fixed in code):

1. the exported plugin object must itself declare `inject: ['extension']`; the
   daemon compares the export's inject map with `agnes.plugins[].inject` and a
   mismatch is `E_ROW_METADATA` — the row never activates;
2. `ctx.log` is a Cordis service that needs its own inject; the row logs through
   `ctx.extension().ctx.log`;
3. this daemon build caches an installed tree per package id, so re-installing
   from the same source ref can serve a stale snapshot — the E2E stages a fresh
   copy per run and resets its home.
